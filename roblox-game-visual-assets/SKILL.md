# Roblox 视觉与资源

确保视觉资源可追溯、可授权、可安全接入，并能被玩法与 UI 以稳定身份消费。开始前读取冻结的视觉来源/版本/用途、还原目标视图、DataModel 路径和资源预算及[Studio 插件路由](../roblox-development-workflow/references/studio-plugin-routing.md)。未知的机位、FOV、视口或尺寸保持未知，不能根据效果图外观编成实测值。

先按[视觉工作流](../roblox-development-workflow/references/visual-workflow.md)读取当前视觉基线，再按[共享资源登记与使用](../roblox-development-workflow/references/shared-asset-usage.md)查单一资源总表、消费者、许可和实际路径。模型生成、切分、材质配对、原位贴图替换及资源就绪边界均以该参考中的当前 Studio 工具事实为准。

本地文件按[工程目录与产物归档](../roblox-development-workflow/references/project-layout.md)区分临时加工、待确认、已确认交付和正式游戏资源；正式模型、贴图、材质、UI、图片、动画及特效分别放入 assets 的对应类型目录，确认与消费证据保存到工作流目录，不把完整效果图当作运行资源。

V3 负责正式资源生产、资源级人工接受、资源身份与登记；V4 才正式装配场景、接线和回读 Edit 源。开始 V4 组合前核对 V0–V3 退出及复用范围；生成资源成功、ready 或全局方向批准不能补齐对象阶段，也不证明消费界面已验收。按[阶段契约](../roblox-game-workflow-control/references/stage-contract.md)分别保留资源交付、场景组合、正式源回读与当前仍需完成内容。

V2 先按[视觉拆解交付](../roblox-development-workflow/references/visual-decomposition.md)从冻结 V1 图枚举显著特征，确定图片、Roblox 原生、复用、模型、材质或特效路线，并在编号中文标注图中写明消费与生产边界。同步填写同一拆解合同的 `restoration`：绑定目标机位/FOV/视口/构图锚点，逐项指定轮廓、比例、位置、空间层次、色板、材质、纹理尺度、光照、水面/岸沿等显著表现及其生产方法、消费者和验证方式。只有真实测量才标 measured；未知和不适用都注明原因。复用公共资产仍保留本地拆解编号及公共修订；原生项和原子资产内部特征也不能遗漏。拆解图片交给 image_generator 制作并直接展示；禁止裁切效果图充当正式资源，不能因程序能绘制就降级特色视觉。

模型工作必读[3D 模型 V2 选型、V3 资源生产与 V4 场景接入](../roblox-development-workflow/references/model-production.md)：先按拆解逐组件路由到网格或可调程序化生成，具体判断依据见[按拆解结果路由生成模式](../roblox-development-workflow/references/model-production.md#按拆解结果路由生成模式)，并确认工具能否直接使用冻结参考图；文本路线只产生待审候选，须检查轮廓、比例和风格。V3 对当前候选的全部 V2 组件取得资源级人工接受，`outputs` 分别引用项目内原生制作源文件或资源总表当前修订；视觉资源预览逐项绑定相同引用。没有新资源也要确认复用范围，不能以 ready 代替接受。V4 按目标机位组合代表性场景样板并按项目策略接受，然后才可扩展场景铺设。非等比缩放说明必要性，并复查造型与纹理尺度；现有模型的材质/贴图加工不等于重新生成几何。生成/上传授权不代表视觉接受。按[内部交付模板](../roblox-development-workflow/assets/templates/model-production.md)记录真实生产、审查和 Edit 回读事实，不把 Completed 当接入成功。

3D 的默认执行链路使用 Roblox Studio 插件：查询/复用 → V3 生产候选并审查 → 当前资源范围人工接受 → 资源身份登记 → V4 按目标机位组合场景样板并检查 → 按现有视觉策略取得样板接受 → 扩展场景铺设 → Edit 回读与消费登记。V4 样板状态留在现有 `stageReviews.production` 中，不另设阶段或状态系统。普通方法选型不增加批准流程；样板接受遵循项目既有视觉检查策略，只有明确授权自动视觉检查时才用自动结论，并保留其与人工确认的区别。只有用户明确指定或已核实的 Roblox 能力缺口需要改变生产体系时，才处理相应替代决定。

按[资源消费绑定](../roblox-game-workflow-control/references/asset-bindings.md)登记资源修订、当前/历史消费者及消费工作项的 Edit 回读；资源换版、退役或许可失效时，先处理实际受影响消费者，不以生产者 PASS 代替消费验收。

## 职责与输入

- 先查询当前 Experience 中已使用的资源 ID、模型结构和许可记录；对需求澄清用途、视距、风格、性能目标与生产来源。
- Studio 的 search_asset 用于查找候选；核实来源与使用权后，insert_asset 只将候选导入 game.ServerStorage 隔离审查，不直接放入运行容器。
- 将模型、材质、贴图和程序化模型生成分别路由到 generate_mesh、generate_material、generate_texture、generate_procedural_model；具体参数依工具实际 schema，不臆造参数。
- 需要新绘制的位图、插画、图标或纹理概念图时交给 image_generator；不要把 3D 生成工具当成位图生成接口。
- 关键视觉方向、版权替代方案或外部成本有实质选择时交给策划；实施者可自行处理已确定方向内的普通细节。
- 若视觉方向、参考图用途、资源许可、生成范围或生产成本无法由项目记录和来源证据确认，交给[Roblox 游戏拷问](../roblox-game-grilling/SKILL.md)逐项澄清并记录批准范围；资源检索结果不替用户作许可或风格决定。决定后回交原资源工作项。

## 执行步骤

1. 为每项资源记录稳定名称、用途、消费者、来源、作者/许可、来源地址或 Studio 返回身份、版本和替换责任人。
2. 先复用已获准并符合预算的资产；搜索结果只是候选，不代表许可、质量或脚本安全已经验证。
3. 从 Creator Store 或外部渠道候选先核实来源与使用权，再通过 insert_asset 导入 game.ServerStorage 隔离审查；检查前不执行脚本、不 require ModuleScript，也不启动 Play。用实例与脚本只读工具检查完整层级和行为，移除或拒绝不必要、混淆或具有远程/数据访问能力的脚本，审查完成后才将许可资产正式接入。
4. 对模型记录尺寸/轴向、碰撞、层级、材质槽、纹理分辨率、透明/特效数量、LOD 或可见性策略和目标设备预算。
5. 对每项资产确认 assetId/资源字段、使用权限、加载路径、Streaming 假设和缺失时的安全占位行为；不要猜 ID 或复制来源不明内容。
6. 由资源所有者接入，玩法/UI 只消费登记后的资源，不在消费侧私改共享源或复制出未登记版本。
7. 对生成或导入结果回读真实实例与引用，检查加载、尺寸、材质、动画归属、脚本、控制台错误和资源预算。

## 交付与验证

- 交付资源登记表、来源与许可证据、真实 assetId、消费者路径、导入或生成事实、性能预算和已知限制。
- 通过 search_game_tree、inspect_instance、script_search、script_read 核验实际接入；工具未提供的状态标为未验证。
- 若视觉效果需要截图确认，按项目既有检查策略提供当前候选截图和检查要点；要求人工确认时由用户确认显示效果并留真实来源。只有用户明确授权自动视觉检查时，才在授权范围内自动检查并标记 automatic，不冒充人工确认；无此授权不得自动分析截图。
- 动画和材质消费路径交接给 [玩法开发](../roblox-gameplay-development/SKILL.md) 与 [反馈动效](../roblox-game-juice/SKILL.md)，许可证据交给 [发布](../roblox-game-release/SKILL.md)。
- 没有权属证明、资产夹带未经审查脚本或性能开销无预算时，标为阻断并给出安全替代路径。

不得把搜索到、生成成功或能插入的资源称为已授权或已通过 QA。不得未获授权上传或发布资源。

## 资源信任与交接

- 对导入模型检查 Script、LocalScript、ModuleScript、隐藏对象和自动运行行为，核验后才考虑接入。
- 对资源作者与发布者不一致、许可语义不清或权限不可核实时保持未接入。
- 标明哪些模型允许修改、哪些是共享源、哪些仅能在单一消费者中使用。
- 对动画标明 rig 类型、角色绑定假设、动画所有者和目标 AnimationId。
- 对动态模型、粒子和透明材质说明是否可能造成客户端帧耗、内存或透明排序成本。
- 说明资源加载失败、私有资源不可见和审核延迟时的替代体验。
- 将正式接入和版本替换交给资源登记的单一所有者，消费者不得私自覆盖原资产。
- 资源截图应与实际候选版本和消费者路径对应，不能用概念图代替 Studio 结果。
- 生成内容的来源、许可和实际使用范围需进入发布清单。
