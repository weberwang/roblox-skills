# Roblox 共享资源登记与使用

在视觉拆解、资源生产/插入、跨工作项复用和资源变更时读取。项目唯一资源总表为 `docs/asset-register.json`，其格式、精确字段、创建和检查由[项目文档与清单工具](project-artifacts.md)维护；本文件只规定资源身份与接入证据，不另加 JSON Schema 或第二份账本。每个工作项遵守[视觉工作流](visual-workflow.md)的 `visualContractRef` 和现有单写者边界。

按[工程目录与产物归档](project-layout.md)保存本地文件：正式游戏资源进入 `assets/<类型>/<资源ID>/r<修订>/{source,runtime}/`，候选交付进入 artifacts，来源/许可/回读等证据进入 `.workflow-control/evidence/`。资源总表引用实际文件与真实 DataModel/Asset ID，目录归档不替代许可、ready 或用户视觉接受；Studio 独有资源不伪造本地导出。

## 何时可以共享

资源的 `revision` 与消费者的 `state`、`candidate`、`revision` 使用[资源消费绑定契约](../../roblox-game-workflow-control/references/asset-bindings.md)。工作项 `assetBindings` 必须精确绑定当前 active 消费与 Edit 回读；改版、退役或许可失效会阻断这些消费者。退役的历史引用保留为 historical，不要求无关工作项为历史记录重新验收。

只有多个实际消费者已确认使用同一版本、来源和规格，且许可、质量与预算均已核实时，资源才可标记为可复用。视觉相似、同名、同用途、工具生成成功或已插入 Studio 都不足以证明可共享。尚未核实的来源/权限、消费者或实际消费结果时，维持候选，不让下游当正式依赖。

资源记录至少能回答：

- 稳定且项目唯一的资源 `id`、类型、用途、来源/生产者、版本和唯一维护者；
- 作者/来源、许可文本或可访问证据、使用范围，以及尚未解决的权限状态；
- 实际 Roblox `assetId`（若有），或真实 `game.` 实例路径/项目加载路径。程序化生成或仅在 DataModel 内组合的资源可没有 assetId，但必须记录当前实际路径和消费者；
- 每个消费工作项、完整节点/实例路径、状态或视口、接入版本、生产/回读证据和预算；
- 替换责任、失败占位/降级方式及变更后需复验的消费者。

总表由当前工作项指派的单一写者更新；生产者与消费者把独立事实交给此写者，不并发覆盖全表。总表中的 `id` 在所有调用、拆解和消费合同中保持稳定；源资产版本或真实 ID 改变时记录新事实，不复用旧版本的验收结果。

## Studio 资源路线的真实边界

开始生成/导入前检查插件当前 schema，并在批准的目标 Studio 中确认写入位置、预期结果和现有引用。常用路线应按目标选择：

V2 的具体选型、参数与参考输入，V3 的资源生产、接受和登记，以及 V4 的场景装配与消费回读见[3D 模型生产与接入](model-production.md)。本页维护公共资源身份与共享边界，生产规格写入原阶段文档；不要把两者复制为第二份资源账本。

| 需求 | 当前工具事实与接入规则 |
| --- | --- |
| 文本生成网格 | `generate_mesh` 生成带纹理的网格。按当前 schema 传参；显式分段最多 8 个部件，`maxTriangles` 范围为 12–20000。完成后仍要核实实际 Model/路径、尺寸、轴向、Pivot、碰撞、材质、贴图和目标设备预算。 |
| 可调程序化模型 | `generate_procedural_model` 以基础几何创建带可调属性的模型，默认 async=true，并自动插入 Workspace。参考图通过真实 `attachedImageUri` 传入，prompt 沿用用户原话；完成后读取新实例、属性、脚本和子级，不重复再创建或默认已通过许可/脚本审查。 |
| 网格拆分 | `segment_mesh` 接收既有 MeshPart/Model 和最多 5 个名称，返回含分段的**新 Model**并插在源对象同级。保留源对象，记录新旧路径与消费者；分段名称或几何不证明已经存在 Rig、Motor6D/Bone、UV、蒙皮或动画。 |
| 材质变体 | `generate_material` 返回的 `BaseMaterial` 与变体名必须同时对应 BasePart 的 `Material` 与 `MaterialVariant`。只记录工具返回的真实配对并回读消费者；名称相似不能代替 BaseMaterial 一致。 |
| 网格贴图替换 | `generate_texture` 在源 MeshPart/Model 上原位替换外观；Quality 模式目前只支持单 MeshPart。先确认目标是独占版本而非共享源，记录原状态/实际路径，替换后重查所有真实消费者。 |
| Creator Store 候选 | `search_asset` 的结果只是候选。按许可与来源审查后，用 `insert_asset` 放入隔离位置并检查完整实例树及脚本；未审查前不运行其中脚本、ModuleScript 或加载逻辑。 |
| 新绘位图 | 纹理、图标、插画等实际位图任务交 `image_generator`。`store_image` 只把本地图片转为 Studio 可引用的临时 `IMAGEID`，不等于上传或发布；`upload_image` 是外部写入，须符合该工作项的明确授权。 |

网格生成、切分与贴图工具都不能代替人工/外部工具制作 UV、Rig、蒙皮或动画。没有实际产物、来源、权限或对应能力时，相关字段保持未验证/阻断，不从网格外观推断已完成。

模型规格至少明确实际世界尺寸、朝向/坐标轴、Pivot、碰撞与交互边界、层级/部件数、材质和贴图来源/分辨率、透明效果成本、Rig/动画接口（如需要）、流式加载假设和目标设备预算。贴图与变体变动需要回读真实实例值；多处消费者都引用共享源时，替换须由资源唯一所有者执行。

## 就绪、消费与失效

1. 生产前查询总表、Studio 中的真实资源路径和下游需求，确认共同消费者、规格、来源与许可。只对确实共用的资源建立共享身份；单一场景的变体留在其专属记录。
2. 交付前把真实 `assetId` 或 Instance/加载路径、资源版本、许可证据和消费者节点补入唯一总表。若尚未加载、许可待核、预算未测或用户视觉判断未完成，按项目状态格式标为候选/未就绪。
3. 每个消费者在自己的场景/UI/运行用例中回读实际绑定，验证需要的状态、尺寸、材质和加载失败表现。生产者技术 `PASS` 不等于消费者接入 `PASS`。
4. 资源内容、来源 ID、材质、加载路径、Rig 或权限改变时，只让受影响消费者重新检查其真实使用的状态与路径；保持无关消费者已有证据有效。不能确认全部间接引用时不删除或覆盖共享源。

如果资源来源或权限无法核实、模型夹带未经检查脚本、资源无法由目标 Experience 加载，或实际开销超过已同意预算，则停止接入并记录失败原因和可行的本地/许可替代路径。上传、公开发布、云资产覆盖或付费行为按对应项目授权处理。
