# 最小提交与恢复

目标是新检出工程后，按 README 恢复工具、读取当前设计和工作项，并继续既有阶段，而不依赖旧电脑的未提交文件。目录职责以[项目目录规范](project-layout.md)为准；此处只定义 Git 提交边界，不引入第二份工作流清单或验收状态。

## 必须提交的最小集合

| 文件或范围 | 最小保留内容 |
| --- | --- |
| `.gitignore`、`README.md` | 忽略规则；工具/技能安装来源和固定版本或提交、恢复命令、正式源位置、验证入口与未完成事项 |
| 项目现有 `AGENTS.md` | 影响后续推进的项目专属规则；没有专属规则时不为占位新建 |
| `docs/project-profile.json`、`docs/GDD.md`、`docs/TDD.md`、`docs/module-manifest.json` | 四份核心档案与设计；未配置状态照实保留，不为提交伪造 ready |
| 已启用的 `docs/asset-register.json`、`visual-baseline.json`、`qa-plan.md`、`release-checklist.md` | 只创建和提交实际使用的可选文件；已有并仍参与工作流的文件不能漏掉 |
| `.workflow-control/project.json` | 完整项目启用项目清单时提交；局部任务未启用时不补空清单 |
| `.workflow-control/work-items/*.json` | 完整项目提交清单登记的全部工作项，包含已完成前置；局部任务提交本工作项及其递归依赖 |
| 被上述文件直接或间接引用的 records、decisions、evidence、artifacts 文件 | 保留阶段规格、合同、必要图片、真实确认来源、失败与复验依据；以引用为准逐文件纳入 |
| 实际正式源、实现配置和必要验证文件 | 文件工程提交已实现的 src、实际同步/构建配置、必要脚本/测试及已有依赖清单和锁文件；Studio 工程按下述正式源规则处理 |
| 当前实现及后续必要修改所需的 assets 文件 | 逐资源保留不可再生制作源、实际运行导出或可核实的稳定外部定位；本地路径被引用时仍须保留对应文件 |
| `.gitattributes` | 使用 LFS 或其他影响检出的属性配置时提交；LFS 指针对应的对象必须能从已配置存储取得 |

这里的“最小”是保留记录的完整依赖集合。不能仅提交几个 JSON 而遗漏它们要求存在的文件，也不能只提交当前活动工作项而丢失项目清单登记的前置交付。尚未创建的计划路径不要求制造文件；已存在且用于当前实现的文件不能按“计划可缺”省略。

## 按引用选择产物

从上述设计/总表、项目清单和保留工作项开始，依次纳入它们引用的文件，再纳入这些文件继续引用的本地依赖。至少核对阶段 `path`、`decompositionRef`、`visualContractRef`、`decisionRefs`、`evidence[].path`、`evidenceRef(s)`、复用来源及源图/标注图等真实文件字段；按字段语义区分文件路径、实例路径、URL 和消息引用，不能把所有字符串当成本地文件。

例如 V2 合同引用 approved 下的 V1 源图和 candidates 下的 V2 标注图，两张图都要提交；当前阶段仍等待用户确认时，已展示的候选也属于恢复所需文件。不能因图片未确认或位于 candidates 就漏掉它。复制到 approved 后，若历史交付仍引用原 candidates 路径，两处被引用文件都保留；不为省空间改写历史确认、覆盖冻结图或删除失败事实。

evidence 只提交记录实际依赖的输出及理解失败/复验所需内容，无引用、可重建的调试转储无需纳入。提交前尚未绑定的原始测试输出可先提取真实、足以追溯的必要证据再登记；已绑定的证据文件按原样保留。archive 中未被当前状态、依赖、决策替代链或资源历史引用的独立旧档案，可放到已有历史提交或项目长期存储；不要为减少提交量自动归档或删改仍生效的记录。

用户确认不能只留“已确认”三个字。保留原有真实消息/收据引用和确认范围，关联可定位的确切候选。若新协作者无法访问原确认来源，恢复说明标明该限制，不能伪造确认或将缺失验收写成 PASS。

## 正式源和游戏资源

文件为正式源时，提交代码、必要资源、实际同步映射以及使它们可复现的配置；可由这些正式源确定性生成的 Place 导出、构建输出和依赖安装目录不重复提交。非确定性的 AI 生成资产不能只凭提示词认定可重建，应保留采用版本的实际文件或已核实可恢复的资源定位。

Studio 为正式源时，单独的 `game.` 路径、Studio 会话 ID 和普通 Asset ID 不能恢复脚本或整个 Place。至少具备一条真实可用的恢复路线：提交已实际保存的 `places/<Place标识>/` 源文件，或在项目档案/README 中记录已获授权且真实保存的云端 Place、确切版本及协作者访问方式。当前源只存在于旧 Studio 内存时，Git 中的记录不足以继续实现，应明确标为源数据未持久化；不能为了满足提交规则自动保存、上传或发布。

资源已通过可访问的 Roblox 资源定位提供，且没有本地路径依赖或后续制作需要时，不重复提交下载缓存；记录真实资源身份、修订、许可和消费者。不可重建的制作源、仍被本地引用的导出与冻结视觉图片仍属于必要文件。大文件可经项目已有 LFS 保存；仅写一个远程地址不能满足现有合同对本地图片/证据文件的要求。

## 不提交的文件

- `.tmp/` 中未被持久引用的缓存、加工中间文件与未采用预览。
- 没有被保留记录引用、后续工作也不需要的候选、重复导出和调试转储。
- 可由固定来源重新安装的 `.agents/skills/`、依赖安装目录和工具索引；项目自定义技能或修改不能只留在被忽略的安装副本中，应另存可恢复的受控来源。
- 具备实际重建命令的构建缓存、临时 Play 对象导出、编辑器自动恢复文件和机器配置。
- 凭据、令牌、私钥等秘密；恢复说明只记录凭据配置方式。
- 空目录的 `.gitkeep` 等占位文件；空目录由 `init-layout` 按需恢复。

最小忽略模板见[游戏工程 Git 忽略模板](../assets/templates/game-project.gitignore)。它只忽略确定的本地临时或安装产物，不按扩展名忽略所有图片、模型、日志或锁文件，也不整体忽略工作流目录。其他生成目录需先确认没有正式源/记录依赖，再按项目补充。已有 `.gitignore` 合并所需规则，不覆盖原内容；此模板不用于技能源码仓库本身。

## 提交和恢复检查

阶段交付通过并完成规定验证后，代理自动在当前分支创建本地提交。按本节清单只选择当前工作项必要文件及其递归引用；提交前核对每条路径归属本任务，并检查 `git diff --cached --name-status`，不纳入其他任务或用户已有暂存内容。对必要文件用 `git check-ignore -v -- <实际路径>` 排查错误忽略规则；处理规则原因后再暂存。禁止以整目录或 `--all` 暂存扩大提交范围。文件归属不清或验证未通过时不提交，保留现场并报告具体原因。只提交当前分支，不创建分支/worktree、不 push；CLI 不执行 Git 命令，实际提交由代理完成。

首次恢复时按 README 安装固定版本工具/技能，运行 `init-layout` 重建空目录，再运行 `check-layout`、`check-docs`、相关工作项 `status`/`stage-status` 和按需 `check-project`。未完成工作项的 `check` 可以继续报告真实 blockers；恢复前后缺项和阻断应一致，不能新增“本地证据不存在”等由漏提交造成的问题。配置完成的项目再按原测试等级执行必要技术验证，截图仍由用户检查。

这些检查只读取本地工作树，不能证明文件都已进入 Git。检查时逐项比对提交清单与必要引用；需要进一步验证时使用临时导出的受控文件副本核对，禁止自动建分支/worktree、启动 Studio 或触发外部操作。`check-layout` 不执行 Git 跟踪扫描，也不证明恢复完整。
