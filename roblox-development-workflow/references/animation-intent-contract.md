# Roblox 动画意图与接入合同

动画是已定义玩法事件的表现。玩法工作项拥有事件语义、权威触发与数值；动画生产者拥有源文件和资源发布；消费脚本负责加载、播放和清理。此合同连接[视觉工作流](visual-workflow.md)、[共享资源登记](shared-asset-usage.md)和[反馈动效技能](../../roblox-game-juice/SKILL.md)，不增加阶段或文字确认门。

## 制作责任与动画规格

在任何动画被标成正式依赖前，工作项须指定实际制作人/工具、交付物、资源所有者、Rig 版本、发布责任及验证人。制作来源可为用户/团队在 Studio 中实际创建并发布的动画、获许可的既有 Animation 资产或已批准外部 DCC 交付；当前 Roblox Studio 插件工具表没有自动 Rig、关键帧录制或动画导出工具。插件可检查 DataModel、脚本、属性和已接入 ID，但这些能力不能冒充动画制作或预览。

每个动作逐项记录：

- `actionId` 和 `workItemId`；玩法事件来源、玩家需要理解的状态/结果、触发端和实际确认时机；
- 表现意图、角色或对象、动画 Rig 类型，以及实际 `Motor6D` / `Bone` 路径、绑定版本和 Animator 实例路径；
- 动画生产者、源文件位置、发布状态、实际 `AnimationId`、创作者/群组归属和目标 Experience 的使用权限证据；
- 消费脚本完整路径、运行侧、具体载入/播放接口、触发参数、时长、过渡、优先级、循环和结束条件；
- 动画 marker/事件名称、发生时点、消费端与语义。Marker 只能发出已约定的表现信号；命中、奖励、位移、伤害和存档仍由对应玩法/服务器规则裁定；
- 重复触发策略（重播/重置/合并/限频/忽略）、竞争动作的打断规则、拒绝/失败回退、重生/离场/对象池回收时的停止及连接清理。

每个动作独立设定时长和事件时点；记录值来自实际资源或经用户批准的动作目标，不为批次强制等长。缺少生产者、Rig、发布权限、加载路径或失败回退时，动画保持未分配/未就绪，不交由玩法侧猜补。

## Animator、权限与 Roblox 实际约束

- `Animator:LoadAnimation()` 执行时，Animator 必须已经是 `Workspace` 的后代。先回读目标角色/模型树和 Animator 位置，再连接载入；不要在对象还未进入世界时就假定动画可播放。
- Animator 应由服务器创建并复制给客户端。玩家角色动画可由角色所属客户端加载并启动后复制；NPC 动画由服务器加载/启动。按角色类型和实际脚本运行侧核实，不能仅凭脚本位于哪个服务文件夹推断复制行为。
- 动画需真实发布且对 Experience 可用。群组体验要核实动画资产 Creator/群组归属与目标体验的权限；工具返回一个 `AnimationId` 字符串不证明其已发布、可访问或 Rig 兼容。
- `Animator`、`Motor6D` 和 `Bone` 结构必须来自实际目标 Rig；生成网格或调用 `segment_mesh` 不会自动生成 Rig/蒙皮或可驱动动画的关节结构。
- 当前插件可通过脚本/实例工具进行接线和只读检查，没有专用动画编辑、录制、导出或运行视觉捕获工具。`screen_capture` 的契约仅支持 Edit 画面；动画是否可读须由用户检查当前实际 Play 画面/视频，工具无法提供证据时记录 `NOT_RUN`。

官方参考：[Animator](https://create.roblox.com/docs/reference/engine/classes/Animator)、[使用动画](https://create.roblox.com/docs/animation/using)、[脚本位置与运行方式](https://create.roblox.com/docs/scripting/locations)、[资产权限](https://create.roblox.com/docs/projects/assets/privacy)。

## 接入与验收步骤

1. 先由玩法/制作确认事件触发与权威结果，再确认真实动画生产者、目标 Rig、Animator、资源所有者和许可证据。
2. 验证动画已发布、AnimationId 可由目标体验访问、目标角色的关节/骨架与资源版本相符。按玩家角色或 NPC 选择正确的运行侧；若插件工具未提供相关能力，不使用未知 API 绕过权限。
3. 在对应消费脚本中接入加载、触发、重播/中断和停止逻辑，并记录实际脚本路径。不同动作或效果不能无约束地争写同一关节/状态。
4. 用已授权的代表性 Play 流程覆盖正常触发、快速重复、取消/失败、被更高优先级动作打断、Character 重生、玩家离开和资源加载失败。实际时长、marker 次序与回退行为记录在当前 Work Item 证据中。
5. 由用户检查当前运行姿势、节奏、连接区和可读性；技术参数或动画轨道存在不能自动填写 `visualReview.qualityResults`。

每个证据绑定当前候选、Rig 版本、AnimationId、消费者脚本与实际目标情境。重复动作状态或 Character 更换时旧 Track、事件连接和延迟任务必须清理。缺失任何实际播放证据时，相关视觉情境保持 `NOT_RUN`；若 marker 会影响玩法结算，则在职责边界评审中阻断并改由权威逻辑实现。
