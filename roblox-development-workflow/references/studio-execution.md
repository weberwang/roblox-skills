# Studio 执行契约

## 一次安全写入

1. 核对当前工作项的 studioId/Place、所有权、源数据与现有模式；重要编辑前保留目标脚本内容、实例关键属性和用户已有改动。
2. 先用查询工具读取精确目标，再决定最小修改。同名实例可能使一条路径匹配多个对象；核对父级、类型、属性和可用 uniqueId，不能默认取首项写入。multi_edit 的 old_string 必须精确匹配，连续编辑按前一条结果执行；新 Script/LocalScript/ModuleScript 明确 className 与源内容。
3. 实例属性、层级、标签和资源绑定通过已核实的 execute_luau 实施；仅修改声明实例，不清空 Workspace 或重建整个工程。运行模式临时改动不能冒充 Edit 模式持久实现。
4. 回读脚本、目标对象属性/引用和 Console。工具成功只证明调用完成，必须再核对预期行为与未引入错误。
5. 本地源码同步项目优先改源文件并使用已有同步链路，核实 Studio 回读；不直接改 Studio 后任由同步覆盖。

## 主线程与异步

execute_luau 在 Studio 主线程执行，长循环可能冻结 Studio、断开 MCP。按逻辑区域或小批次处理，批次之间 task.wait()；不要每个实例都 wait，也不要先构建巨大树再一次 Parent 到 DataModel。每批挂入的小子树也要限制规模。

等待状态的循环必须 yield，并有超时与失败出口。先检查对象存在、类型和预期父级，再实施；对有副作用的操作不要断线后盲目重放，先回读确认是否已执行。

生成任务保留 studioId、jobId、预期对象与影响。generate_procedural_model 默认后台执行并直接插入，不重复再创建；仅用户明确要求等待或后续动作依赖结果时调用 wait_job_finished。原位贴图替换前保存来源与还原信息。

后台任务从启动到终态及结果回读持续占用相应 Studio 写者，不能把异步返回当成写入结束而向同一 Studio 发起其他写入；期间可继续本地文档或只读调查。受理、Completed、正式接入和验收是不同事实；超时或断线先核实同一 job 与实际产物，不盲目重放有副作用调用。原始错误、失败和后续修复分别保留。3D 产物的具体生成、接入和回读按[模型生产流程](model-production.md)执行。

## 运行上下文

Edit 用于正式实现；Client 检查输入、PlayerGui、相机与表现；Server 检查权威规则、存档与多人状态。切换前调用 get_studio_state，不在 Play 状态请求 Edit 树。

用户已在运行时，优先复用并保持其状态；不能为一次静态调查启动/停止 Play。任务需要本地 Play 验证时，在已授权开发范围内执行，并在报告标明进入/退出状态。服务端一次断言不代表客户端 UI 可用。

## 保存与恢复

写入 DataModel、保存本地 Place、保存到 Roblox、公开发布是不同动作。当前工具没有专用保存/发布入口；先准备可检查候选与改动说明，再通过已核实路径取得真实保存证据或请用户完成必要操作。不能因为没有 Console 错误就声称已保存。

恢复仅作用于本任务目标与已捕获基线，不覆盖用户并行改动，不批量 Destroy 未知对象。Team Create 权限、云资源、DataStore API 开关和商店配置属于独立影响面，不在普通场景开发时擅自更改。
