# 3D 模型：V2 选型、V3 资源生产与 V4 场景接入

本地中间文件、待审候选、已确认交付、正式资源与生产证据按[工程目录与产物归档](project-layout.md)分别保存；正式模型文件归 `assets/models/<资源ID>/r<修订>/`。本地路径与 Studio 临时/正式父节点分别记录，目录归档不代表已经插入、保存或上传资源。

涉及场景模型、道具、建筑或可调几何时读取。本流程复用[阶段契约](../../roblox-game-workflow-control/references/stage-contract.md)、[视觉拆解合同](visual-decomposition.md)、[V4 场景样板门](visual-workflow.md#v4-代表性场景样板门)和[唯一资源总表](shared-asset-usage.md)。V2 决定生产方法、逐项还原规格和验收方式；V3 生产、审查并接受正式资源；V4 组合场景、回读正式源并验证运行消费。工具存在不代表应当生成，先检查已有合格资源。

**3D 生产默认使用 Roblox Studio 插件流程。** V2 在 Roblox 现有资源、`generate_procedural_model`、`generate_mesh` 和原生几何之间选型；V3 在同一目标 Studio 内生产候选，审查资源并对当前候选的全部拆解组件取得资源级人工接受，再登记正式资源。V3 不完成正式 Scene 装配。V4 按 V2 计划组合代表性场景样板并按当前视觉检查策略接受，随后才扩大场景铺设并回读 Edit 源。外部制作不是默认并列路线：仅在用户已明确指定，或记录 Roblox 的实际能力缺口并确定替代方案后采用；该决定未闭合时只暂停依赖它的组件。已有合格外部来源资源仍可按 REUSE 接入，不因此重开制作流程。

## V2：确定具体生产方法

`productionRoute` 表示产物/来源类别，不能只写 `MODEL_3D` 就完成选型。先按拆解编号查已有合格资源：满足效果、许可和预算时走 `REUSE`，保留公共资源 ID/修订及消费边界；已有几何只改表面时走材质/贴图工序；简单确定形体或精确规则组合可直接走 `ROBLOX_NATIVE`，记录参数和回读。它们是生成前的分流，不是额外的模型生成模式。确需新生成的组件，按下面两种模式的能力和拆解要求选择主方法。

### 两种生成模式的特点

| 判断维度 | 网格生成 `generate_mesh` | 程序化生成 `generate_procedural_model` |
| --- | --- | --- |
| 形体与产物 | 文本驱动的带纹理网格候选；适合需要复杂曲面、自然不规则轮廓或表面细节的组件 | 基础体（块、球、柱、楔体）组成的脚本化 ProceduralModel；适合基础体足以表达的结构 |
| 参考图 | 当前没有图像入参；只能依据文本提示，不能宣称工具直接看过冻结图 | 支持 `attachedImageUri`；有参考图时传真实 IMAGEID，但支持图像输入不代表能表达任意曲面或忠实复现 |
| 可编辑性 | 不能假定能以属性直接调整原始造型；修改轮廓可能需要重生成或其他已核实工序 | 生成用户要求的可编辑属性，便于校准尺寸、颜色、比例和重复结构；仍要检查属性及重建行为 |
| 尺度与成本约束 | `size` 是尝试拟合的包围体积，`maxTriangles` 是预算上限；两者都不是实际测量 | 记录部件预算、结构参数和脚本重建开销；当前没有网格路线的 `size/maxTriangles` 入参，不能移植参数 |
| 主要风险 | 提示可能丢失特征、比例或接缝，文本无法满足硬性图像输入要求；纹理和分件仍需回读 | 基础体可能把曲面/特色轮廓简化成积木，部件和脚本可能增加成本；不能用后期拉伸掩盖不适合的路线 |
| 执行与验收 | 依据实际返回查产物位置，不假定自动插入或已获 Asset ID；先审候选再组合 | 自动插入 Workspace，不能重复创建；审查生成脚本/属性，再组合。两者均不自动具备正确碰撞、Rig、UV 或视觉接受 |

### 按拆解结果路由生成模式

以 `componentId` 为单位读取关联 `restoration.requirements`、冻结来源及目标机位，先识别必须保持的轮廓/比例/接缝、表面细节、参数变化和预算，再路由；不能只按“建筑”“吊机”等物件名称选工具，也不能整场统一套一种生成模式。执行顺序如下：

1. **先核对硬约束**：直接使用参考图、可调参数、精确拓扑/UV/蒙皮等要求分别列出。`generate_mesh` 无法满足硬性直接图像输入；程序化模型也不能因支持参考图就被视为能满足复杂有机轮廓。两者均缺少已核实能力时记录缺口，只暂停依赖组件，不默默降低要求、改用文本替代或默认转外部制作。
2. **结构适合基础体且需要调参时，选程序化**：例如已拆成规则台阶、墙段、支架、横梁，核心验收是段长/高度/间距/比例关系，并需要反复校准或生成系列变体。说明需要暴露的属性和校准方法。基础体无法保持的特征不能列为这条路线已覆盖；尺寸必须精确时优先评估直接原生构建，不把生成属性视为精度保证。
3. **复杂轮廓或纹理网格主导时，选网格候选**：例如自然石块、弯曲装饰或带复杂表面细节的独立外壳，基础体组合会损失显著特征，且文本候选路线不违背参考输入要求。按冻结图的特征与还原要求组织 `textPrompt`，记录文本转译丢失的信息、目标尺寸/预算及轮廓校准计划；不以“低模”或“远景”为由抹掉目标机位仍显著的轮廓。
4. **同一物件同时受两类约束时，按职责拆分**：参数化承重结构可用程序化，复杂外壳/装饰可用网格。在原组件 `productionBoundary` 中为内部生产单元给稳定名称或编号，逐单元记录主方法、Pivot、接口尺寸、接缝、材质尺度和消费者；只有需要独立消费、编号或状态覆盖的单元才提升为正式子组件，同时维护既有父子关系和标注覆盖。最后在同一机位组合检查。每个生产单元只有一个主生成方法；这种组合不是第三种生成模式，也不要求两条路线重复生成完整物件。
5. **不能据现有拆解决定时，保留未知**：写清缺少的是特征、参数、可用图像输入还是工具能力，不凭空填精度或根据生成速度决定路线。不受影响的组件继续准备；补齐依据后更新本组件的现有 V2 规格，不能以生成成功倒推选型正确。

路由结论写回同一组件的 `productionBoundary` 和现有 V2 模型规格：关联还原要求 ID、决定性形体/表面与参数约束、参考图使用方式、主工具、选择理由、另一模式的限制、配套工序、组合接口及样板验证方式。`sourceRef` 保留来源身份，`restoration.requirements[].productionMethod` 定位组件及其生产单元的稳定名称和方法；跨单元的组合要求列出涉及的单元及装配验证，不把多种方法混写成一个单元的主工具。多个要求共享同一单元时引用该路由，不复制多份相互冲突的方案。内部规格可用[模型生产模板](../assets/templates/model-production.md)中的逐组件路由表，不增加模型专属 JSON 字段或独立控制面。当前结构检查器不理解这些自由文本，不能将“已填写”报告成“路由正确已获机器认证”。

例如拆解确实表明港口局部由重复墙段、可调横梁、自然碎石和水面构成时：规则墙段/横梁按参数需求评估程序化或直接原生，碎石按轮廓需求评估网格候选或复用，水面单独落实材质/原生水体及光照要求。最后以岸墙＋水面＋吊机局部组合验证；这个例子不预设当前项目一定包含上述特征，也不将道具生成当成水面和环境层次已完成。

需要精确拓扑、UV、蒙皮、Rig 或特殊制作规范时，先核实 Roblox 当前能力和现有合格资源。确实无法满足才记录受限替代方案的工具/负责人、交付格式、来源许可、接入方法及剩余缺口；不自行切换生产体系，也不能把生成网格或部件名当成骨骼/动画。

已有模型只换表面时保留原几何，按需选 `generate_material` 或 `generate_texture`；不要无故重新生成模型。固定的复杂表面、纹理、光影与特色轮廓不得仅因原生实现更省事而降级。确需改变 V1 目标、预算或来源时，按既有决策交接处理，只暂停受影响工作。

每个模型组件的内部 V2 规格至少包含：选择的方法和理由、参考/提示来源、尺寸/轴向/Pivot、部件与消费职责、碰撞/锚定/交互边界、材质与贴图工序、是否需要 Rig/动画、实例/网格/纹理预算、Streaming 假设、所有者、临时产物和正式父节点、验证及失败恢复计划。与此同时在 `decomposition.restoration` 中将模型轮廓、比例、位置、表面、光照与显著特征映射到对应组件和目标视图；水面、岸沿、背景层次等环境表现即使不是道具模型，也必须有明确生产/消费/验证要求。工具参数预算与实际测量分列，未知且影响实现的内容不能写成已解决。

调用生成前，逐项说明所选工具能否直接接收冻结参考图及实际图像入参，并将路由用的内部规格与真实调用输入分开记录。程序化工具的 `prompt` 保留用户原话，不能把代理拆解/推断写成用户描述；只有图无文字仍传空字符串。内部确定的目标通过符合工具契约的参考图、已核实可调属性及后续装配校准落实，不能假设内部规格已作为隐藏参数传入。若现有原话和图像不足以指明要生成的组件，记录这一输入缺口，不用全场请求冒充单个组件的明确描述。只接受文本的路线应明确按文本生成候选，再按 V1/V2 检查，不得称为已经忠实还原。候选通过轮廓、比例和统一风格检查之前，不扩展到其他实例或批量铺设。若使用非等比缩放，记录必要性，并检查缩放后轮廓、比例、接缝及纹理尺度是否被破坏。临时几何只能标为 `sample` 或 `placeholder`，不能列为最终美术。

这些内容放进现有 V2 阶段文档，可复制[生产交付模板](../assets/templates/model-production.md)作为内部章节。拆解合同中的 `sourceRef` 指向真实来源或规格定位，`productionBoundary` 写明主方法与配套工序，`assembly` / `layoutRef` 写装配与参照，`owner` / `consumerNodeId` 写生产者与消费者；`verificationPlan` 和退出依据定位具体计划。复用项仍绑定公共资源身份，不以规格路径覆盖来源身份。无需新增工作项字段或第二份资源登记表。

V2 用户侧仍按[编号框选中文标注图](visual-decomposition.md)直接交图：在原编号旁写明 Roblox 内的“网格生成／程序化／原生／复用”选型、生产边界与装配关系；确有已确定的外部替代时单独标明能力缺口与来源。内部生产模板和参数表不替代拆解图。无必要人工决定时沿用 deliverables 连续推进，manual 另需真实阶段确认。

## 工具参数与副作用

以下只说明当前工具定义；执行前重新核对 schema，不假定存在通用参考图参数、保存或发布接口。

- `generate_mesh`：输入 `textPrompt`，可指定 `size: {x,y,z}` 和 `maxTriangles: 12–20000`。当前没有参考图入参，不能给它虚构 `attachedImageUri`；需要图像驱动或精确复现时重新评估程序化或外部路线，不能悄悄丢弃参考要求。完成后依据返回内容核实实际产物位置，不能假定自动插入位置或虚构 Asset ID。
- `generate_procedural_model`：用基础几何生成带可编辑属性的模型，**自动插入 Workspace**，不要再创建一份。默认 `async: true`。`prompt` 传用户原话及其要求的可调属性；用户给参考图时传 `attachedImageUri`，不得自行转述图像内容替代用户描述；只有图而无文字时 `prompt` 为空字符串。
- 本地参考图通过 `store_image(filePath)` 得到工具实际返回的 `IMAGEID_…`，仅支持 PNG/JPG/JPEG、最大 5 MB。不能拼接 IMAGEID，不能把本地路径直接当 `attachedImageUri`，也不把此步骤称为上传发布。超限或不可访问时先取得可用且获准的输入，不默默忽略参考图。
- 两种模型生成的 `segmentation`：用户未提出分件时省略或 `auto`；用户明确要求整体单件时 `none`；用户列出部件时 `explicit` 并给 `partNames`。内部视觉拆解的组件清单不是用户明确列出的部件，不得据此自动设置 `explicit` 或编造用户分件要求；内部组合计划与单次工具调用分件分别记录。`partNames` 是逗号分隔字符串或 JSON 数组的**字符串**，最多 8 项。需求超过上限时安排可追溯的分批组合或其他制作路线，不让工具静默截断必要部件。
- `segment_mesh`：处理已有 MeshPart/Model，指定精确 `instance_path` 和最多 5 个 `parts` 名称；返回源对象**同级的新 Model**，保留并记录源、新对象及消费者。它不是生成时最多 8 件的参数，也不证明拓扑、UV、关节或蒙皮已正确。
- `generate_material`：记录实际返回的 `BaseMaterial` 与变体 `Name`，将二者分别用于 BasePart 的 `Material`、`MaterialVariant` 并回读。输入 `materialId` 不能直接冒充已发布 Asset ID。
- `generate_texture`：在精确 `instance_path` 的源 MeshPart/Model 上**原位替换**。先核对共享消费者并保留可恢复源；优先处理独占候选，不能覆盖共享源后才发现影响面。`Quality` 当前仅支持单 MeshPart；`Fast` 与 `Quality` 的选择及限制应进入生产计划。`hintImage` 是另一种工具入参，不能将程序化模型的 IMAGEID 字符串盲目套用。

仅新绘位图、V1/V2 图片及纹理概念图交给 `image_generator`；Studio 的 3D 生成与模型重贴图由资产实施者通过对应 Studio 工具完成，不把它们误交给位图生成工具。

## V3：正式资源生产、接受与登记

1. **确认阶段和写入基线**：运行 `stage-status` 确认 V2 已退出、当前 active V3。核对真实 Studio/Place/Universe、Edit 模式、源数据与同步链路、写入范围和单写者。记录已有对象、原属性/引用、Console 基线，以及资源正式登记位置；不能清空 Workspace 或覆盖用户并行修改。
2. **生产当前候选资源**：逐个读取 V2 组件路由及要求 ID，再核对当前工具 schema 和真实输入后调用，不用统一网格生成覆盖所有组件。复用/导入同样按已定规格进行；只在当前授权范围内写入，素材上传、付费、云覆盖和公开发布仍分别核对授权。工具不能满足规格时记录限制，回到受影响选型，不用占位形体冒充最终美术。候选因路线能力不适合而失败时，回到该组件的决定性约束重新选型，不靠反复生成或非等比拉伸掩盖缺口；仅个别参数失配时保留合格部分并校准。
3. **跟踪后台任务**：保留同一 `studio_id`、工作项/候选、调用参数、`jobId`、真实结果和错误。异步返回 jobId 只是已受理；只在用户要求等待或后续接入/回读依赖结果时调用 `wait_job_finished`。后台生成仍会写 Studio，单写者占用持续到任务终止且回读完成，期间不向同一 Studio 发起其他写入；可继续本地文档或只读调查。超时、断线或结果未知时先查任务与产物，不盲目重试生成、重复插入或把不明状态标为成功；Failed/Cancelled 保留原始事实和重试来源。
4. **核实候选资源**：按工具返回路径和有界树差异定位实际 Model/MeshPart 及程序化建模结构；有歧义先消除，不取首个同名对象。程序化模型已自动插入，检查实际子级、属性、生成脚本及依赖，区分可调建模脚本与玩法脚本；不要为了“隔离”删除必要脚本或宣称工具生成代码从未执行。外部模型仍按现有隔离审查规则处理，未审查前不执行其脚本。检查候选轮廓、比例、风格、尺寸、部件、材质和来源许可，保留失败与复验来源。
5. **资源级人工接受**：在候选资源预览上取得 `resourceAcceptance:{mode:"manual",result:"PASS",workItemId,candidate,componentIds,userMessageRef,reviewedAt,evidenceIds,outputs}`，覆盖 V2 全部 `componentIds`，每个组件恰有一条纯引用。`ROBLOX_NATIVE` 输出用 `{componentId,sourceRef}` 指向项目内非空原生制作源文件，V3 可准备模块但不接入正式 Scene；其他路由用 `{componentId,resourceId,revision}` 引用唯一 `docs/asset-register.json` 资源条目，且须为当前 ready 修订并有已批准许可及来源/产出证据。已有资源复用也登记相同引用，不复制资源元数据；V3 不要求 V4 消费者或 Edit 回读。人工消息须真实且明确接受当前资源范围；`evidenceIds` 引用当前 visual 资源预览，每条证据的 `resources:{stageReviewId,componentIds,outputs}` 只绑定该预览实际包含的组件，`outputs` 逐项与接受记录中对应引用一致。资源 `ready`、生成成功或技术 PASS 均不能替代接受。未接受时只继续修复资源并复验。
6. **登记资源身份与生产事实**：复用 `docs/asset-register.json` 的 `source.kind/uri/evidenceRef`、`evidenceRefs`、真实 `assetId` 或 `instancePath`、许可、修订及来源。记录资源生产结果和登记事实；V3 不声明消费者已正式装配，不填写 Edit 组合、接线或场景回读完成结论。正式消费者及 `assetBindings` 的 Edit readback 在 V4 完成。

## V4：场景组合、回读与运行接入

只有 V3 资源生产和资源级人工接受通过后，才进入本节。运行 `stage-status` 确认当前 active V4；先按 V2 `restoration.samplePlan` 在指定视图组合最小代表性场景，逐轮将真实视觉证据、`proportion`、`silhouette`、`materialScale`、`seams`、`occlusion`、`depth`、`style` 检查及接受结论记录到 `stageReviews.production.sampleAttempts`。当前样板尚未被接受或必要检查未通过时，只修复和复验样板，不能扩大场景铺设。每次 `scene-assembly` 或 `full-scene-layout` 扩展都在 `stageReviews.production.expansions` 记录范围和其引用的最新已接受样板。

样板接受按项目现有人工/自动视觉策略处理：人工模式须有用户对当前场景样板的真实判断；自动模式仅在明确授权范围内使用。全局方向、资源接受、旧候选/旧截图、“继续”、生成成功、资源 ready 或技术 PASS 均不能代替场景样板接受。接受后由唯一所有者按规格完成正式 Edit 组合、接线、源回读和可查看交付，再完成运行与动态验证。

| Edit 回读对象 | 应核对的实际事实 |
| --- | --- |
| 身份与结构 | 目标 Studio/Place/Universe、DataModel=Edit，实际路径/父级/类型、可用唯一身份、部件名和数量；必要部件未被截断。 |
| 几何与装配 | 实测尺寸/朝向/Pivot、位置、碰撞/锚定、交互与装配节点；生成参数只作目标对照。 |
| 程序化属性与脚本 | 属性名称/当前值、建模脚本和模块依赖、重建时的所有权与清理责任；实际参数调整试验只在已授权范围执行，不把属性存在当成可调行为已验证。 |
| 外观与资源引用 | 实际 MeshId/TextureID/SurfaceAppearance 等适用字段、材质与变体配对、纹理来源与权限；不存在的字段不虚构。 |
| 消费与版本 | 正式消费者路径、当前修订、来源/许可证据、实际 Asset ID 或实例路径；程序化资源无 Asset ID 可用真实 instancePath，不补假 ID。 |
| 预算与限制 | 可取得的实例/部件、材质/透明开销及网格/纹理指标；实际三角数、纹理分辨率等工具未返回时记未验证，并按计划阻断或交接，不能将 maxTriangles 当测量值。 |
| 源与交付 | 正式源/同步持久方式、生成和修改前后记录、Console 增量、可查看候选及人工检查要点；Edit 写入不等于 Place 已保存或发布。 |

## 检查器与资源状态边界

运行加载、输入/交互、碰撞行为、生命周期、Streaming、动画与设备性能均在 V4 按实际需要验证。每项记录已完成的技术事实、未覆盖项与所有者。截图只交用户检查，当前候选未获判断时人工视觉保持 NOT_RUN；网格生成不等于 Rig/动画接线，Edit 回读不等于运行或性能通过。

资源 ready 使用既有状态语义：已满足来源/许可、规格和本资源必要技术验证才能标 ready；仍依赖未完成预算或必要人工判断时保留 planned。V3 的资源人工接受是独立必要门，ready 不能替代它。正式当前消费在 V4 登记，必须满足 ready、当前 revision 与精确 Edit readback；资源技术 ready 和资源人工接受都不能替代 V4 场景样板接受、全场视觉还原或运行/最终验收。

本地控制脚本检查阶段顺序、交付定位、拆解与还原记录结构、V3 资源接受、V4 样板/扩展身份和证据关系及最终消费绑定关系；不会自动核实方法是否合适、生成任务是否真实执行、回读正文是否完整、用户消息是否表达接受或视觉质量是否通过。结构 PASS 只证明记录约束通过，不是画面通过。本流程沿用现有工作项字段和 V4 阶段内部样板记录，不增加阶段或独立状态系统。
