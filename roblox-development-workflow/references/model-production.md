# 3D 模型：V2 选型与 V3 生产接入

涉及场景模型、道具、建筑或可调几何时读取。本流程复用[阶段契约](../../roblox-game-workflow-control/references/stage-contract.md)、[视觉拆解合同](visual-decomposition.md)和[唯一资源总表](shared-asset-usage.md)。V2 决定生产方法和验收规格，V3 才生成、组合与正式源回读；V4 验证运行消费。工具存在不代表应当生成，先检查已有合格资源。

**3D 生产默认使用 Roblox Studio 插件流程。** V2 在 Roblox 现有资源、`generate_procedural_model`、`generate_mesh` 和原生几何之间选型；V3 在同一目标 Studio 内生成，按需切分、生成材质或重贴图，然后装配、登记并回读正式 Edit 源。外部制作不是默认并列路线：仅在用户已明确指定，或记录 Roblox 的实际能力缺口并确定替代方案后采用；该决定未闭合时只暂停依赖它的组件。已有合格外部来源资源仍可按 REUSE 接入，不因此重开制作流程。

## V2：确定具体生产方法

`productionRoute` 表示产物/来源类别，不能只写 `MODEL_3D` 就完成选型。按冻结 V1 的视觉特征、可编辑性、精度、部件职责、预算与实际工具能力确定一种主方法；材质、贴图及后续拆分另记配套工序。可选路线如下：

| 需求与取舍 | 类别及具体方法 | 必须说明的边界 |
| --- | --- | --- |
| 已有资源满足效果、许可和预算 | `REUSE`；查总表，必要时 `search_asset` / `insert_asset` | 公共资源 ID、修订、许可、消费者及替换影响；不因有生成工具而重做。 |
| 需要复杂轮廓和带纹理网格，允许生成候选再校准 | `MODEL_3D`；`generate_mesh` | 文本提示、目标尺寸、三角形预算、拆分需求和后处理；提示尺寸与预算不是实际测量。 |
| 基础几何可表达目标，需可调尺寸、颜色、比例或结构参数 | `MODEL_3D`；`generate_procedural_model` | 用户原话、可调属性、参考图、实例/部件预算与生成脚本审查；输出是带属性的程序化模型。 |
| 简单确定形体或精确规则组合，可直接按现有工程构建 | `ROBLOX_NATIVE`；有界 `execute_luau` / 复用组件 | 计划实例、参数、单写者、分批写入与回读；不能用简单积木降级 V1 要求的特色外形。 |

需要精确拓扑、UV、蒙皮、Rig 或特殊制作规范时，先核实 Roblox 当前能力和现有合格资源。确实无法满足才记录受限替代方案的工具/负责人、交付格式、来源许可、接入方法及剩余缺口；不自行切换生产体系，也不能把生成网格或部件名当成骨骼/动画。

已有模型只换表面时保留原几何，按需选 `generate_material` 或 `generate_texture`；不要无故重新生成模型。固定的复杂表面、纹理、光影与特色轮廓不得仅因原生实现更省事而降级。确需改变 V1 目标、预算或来源时，按既有决策交接处理，只暂停受影响工作。

每个模型组件的内部 V2 规格至少包含：选择的方法和理由、参考/提示来源、尺寸/轴向/Pivot、部件与消费职责、碰撞/锚定/交互边界、材质与贴图工序、是否需要 Rig/动画、实例/网格/纹理预算、Streaming 假设、所有者、临时产物和正式父节点、验证及失败恢复计划。工具参数预算与实际测量分列，未知且影响实现的内容不能写成已解决。

这些内容放进现有 V2 阶段文档，可复制[生产交付模板](../assets/templates/model-production.md)作为内部章节。拆解合同中的 `sourceRef` 指向真实来源或规格定位，`productionBoundary` 写明主方法与配套工序，`assembly` / `layoutRef` 写装配与参照，`owner` / `consumerNodeId` 写生产者与消费者；`verificationPlan` 和退出依据定位具体计划。复用项仍绑定公共资源身份，不以规格路径覆盖来源身份。无需新增工作项字段或第二份资源登记表。

V2 用户侧仍按[编号框选中文标注图](visual-decomposition.md)直接交图：在原编号旁写明 Roblox 内的“网格生成／程序化／原生／复用”选型、生产边界与装配关系；确有已确定的外部替代时单独标明能力缺口与来源。内部生产模板和参数表不替代拆解图。无必要人工决定时沿用 deliverables 连续推进，manual 另需真实阶段确认。

## 工具参数与副作用

以下只说明当前工具定义；执行前重新核对 schema，不假定存在通用参考图参数、保存或发布接口。

- `generate_mesh`：输入 `textPrompt`，可指定 `size: {x,y,z}` 和 `maxTriangles: 12–20000`。当前没有参考图入参，不能给它虚构 `attachedImageUri`；需要图像驱动或精确复现时重新评估程序化或外部路线，不能悄悄丢弃参考要求。完成后依据返回内容核实实际产物位置，不能假定自动插入位置或虚构 Asset ID。
- `generate_procedural_model`：用基础几何生成带可编辑属性的模型，**自动插入 Workspace**，不要再创建一份。默认 `async: true`。`prompt` 传用户原话及其要求的可调属性；用户给参考图时传 `attachedImageUri`，不得自行转述图像内容替代用户描述；只有图而无文字时 `prompt` 为空字符串。
- 本地参考图通过 `store_image(filePath)` 得到工具实际返回的 `IMAGEID_…`，仅支持 PNG/JPG/JPEG、最大 5 MB。不能拼接 IMAGEID，不能把本地路径直接当 `attachedImageUri`，也不把此步骤称为上传发布。超限或不可访问时先取得可用且获准的输入，不默默忽略参考图。
- 两种模型生成的 `segmentation`：用户未提出分件时省略或 `auto`；用户明确要求整体单件时 `none`；用户列出部件时 `explicit` 并给 `partNames`。`partNames` 是逗号分隔字符串或 JSON 数组的**字符串**，最多 8 项。需求超过上限时安排可追溯的分批组合或其他制作路线，不让工具静默截断必要部件。
- `segment_mesh`：处理已有 MeshPart/Model，指定精确 `instance_path` 和最多 5 个 `parts` 名称；返回源对象**同级的新 Model**，保留并记录源、新对象及消费者。它不是生成时最多 8 件的参数，也不证明拓扑、UV、关节或蒙皮已正确。
- `generate_material`：记录实际返回的 `BaseMaterial` 与变体 `Name`，将二者分别用于 BasePart 的 `Material`、`MaterialVariant` 并回读。输入 `materialId` 不能直接冒充已发布 Asset ID。
- `generate_texture`：在精确 `instance_path` 的源 MeshPart/Model 上**原位替换**。先核对共享消费者并保留可恢复源；优先处理独占候选，不能覆盖共享源后才发现影响面。`Quality` 当前仅支持单 MeshPart；`Fast` 与 `Quality` 的选择及限制应进入生产计划。`hintImage` 是另一种工具入参，不能将程序化模型的 IMAGEID 字符串盲目套用。

仅新绘位图、V1/V2 图片及纹理概念图交给 `image_generator`；Studio 的 3D 生成与模型重贴图由资产实施者通过对应 Studio 工具完成，不把它们误交给位图生成工具。

## V3：生成、审查、接入与回读

1. **确认阶段和写入基线**：运行 `stage-status` 确认 V2 已退出、当前 active V3。核对真实 Studio/Place/Universe、Edit 模式、源数据与同步链路、写入范围和单写者。记录已有对象、原属性/引用、Console 基线，以及临时产物父级与正式消费节点；不能清空 Workspace 或覆盖用户并行修改。
2. **执行选定路线**：按 V2 规格调用已核实的生成/复用/导入工具。只在当前授权范围内写入；素材上传、付费、云覆盖和公开发布仍分别核对授权。工具不能满足规格时记录限制，回到受影响选型，不用占位形体冒充正式成果。
3. **跟踪后台任务**：保留同一 `studio_id`、工作项/候选、调用参数、`jobId`、真实结果和错误。异步返回 jobId 只是已受理；只在用户要求等待或后续接入/回读依赖结果时调用 `wait_job_finished`。后台生成仍会写 Studio，单写者占用持续到任务终止且回读完成，期间不向同一 Studio 发起其他写入；可继续本地文档或只读调查。超时、断线或结果未知时先查任务与产物，不盲目重试生成、重复插入或把不明状态标为成功；Failed/Cancelled 保留原始事实和重试来源。
4. **核实实际产物并审查**：按工具返回路径和有界树差异定位实际 Model/MeshPart 及程序化建模结构；有歧义先消除，不取首个同名对象。程序化模型已自动插入，检查实际子级、属性、生成脚本及依赖，区分可调建模脚本与玩法脚本；不要为了“隔离”删除必要脚本或宣称工具生成代码从未执行。外部模型仍按现有隔离审查规则处理，未审查前不执行其脚本。对失败遗留只恢复本任务对象与已捕获基线。
5. **装配与正式接入**：由唯一所有者把已审查的产物接到计划节点，校正尺寸、轴向、Pivot、父级、碰撞/锚定、材质和引用。切分保留新旧对象映射；材质写入成对属性；贴图原位替换后检查引用有无改变，不能凭旧实例路径认为引用仍正确。文件同步工程还要让正式源与现有同步链路一致，避免下次同步丢失生成结果。
6. **回读正式 Edit 源**：使用 `search_game_tree`、`inspect_instance`、脚本只读工具及必要的有界只读 Luau 逐项回读下表，读取 Console 增量。保存实际调用、返回、文件路径和失败，不以生成预览或 Client/Server 临时对象替代。无法取得的属性/指标明确未验证，不能推断通过。
7. **登记与阶段交付**：复用 `docs/asset-register.json` 的 `source.kind/uri/evidenceRef`、`evidenceRefs`、真实 `assetId` 或 `instancePath`、许可、修订及消费者。将生成事实和正式消费回读分开引用，并按[消费绑定契约](../../roblox-game-workflow-control/references/asset-bindings.md)填写工作项与 readback 的 `assetBindings`。V3 的 `sourceReadback` / `wiring` / `editComposition` / `viewableDelivery` 分别定位实际交付和退出依据；只在本阶段必要检查已完成时退出，不以单个 job Completed 抹掉未解决项。

| Edit 回读对象 | 应核对的实际事实 |
| --- | --- |
| 身份与结构 | 目标 Studio/Place/Universe、DataModel=Edit，实际路径/父级/类型、可用唯一身份、部件名和数量；必要部件未被截断。 |
| 几何与装配 | 实测尺寸/朝向/Pivot、位置、碰撞/锚定、交互与装配节点；生成参数只作目标对照。 |
| 程序化属性与脚本 | 属性名称/当前值、建模脚本和模块依赖、重建时的所有权与清理责任；实际参数调整试验只在已授权范围执行，不把属性存在当成可调行为已验证。 |
| 外观与资源引用 | 实际 MeshId/TextureID/SurfaceAppearance 等适用字段、材质与变体配对、纹理来源与权限；不存在的字段不虚构。 |
| 消费与版本 | 正式消费者路径、当前修订、来源/许可证据、实际 Asset ID 或实例路径；程序化资源无 Asset ID 可用真实 instancePath，不补假 ID。 |
| 预算与限制 | 可取得的实例/部件、材质/透明开销及网格/纹理指标；实际三角数、纹理分辨率等工具未返回时记未验证，并按计划阻断或交接，不能将 maxTriangles 当测量值。 |
| 源与交付 | 正式源/同步持久方式、生成和修改前后记录、Console 增量、可查看候选及人工检查要点；Edit 写入不等于 Place 已保存或发布。 |

## V4 交接与检查器边界

运行加载、输入/交互、碰撞行为、生命周期、Streaming、动画与设备性能按实际需要留给 V4；若某项实测是 V3 必要退出条件则不能推迟来冒充已完成。每项记录已完成的技术事实、未覆盖项与所有者。截图只交用户检查，当前候选未获判断时人工视觉保持 NOT_RUN；网格生成不等于 Rig/动画接线，Edit 回读不等于运行或性能通过。

资源 ready 使用既有状态语义：已满足来源/许可、规格和本资源必要验证才能标 ready；仍依赖未完成预算或必要人工判断时保留 planned。尚未就绪的候选消费映射保存在阶段交付，不提前填写 active 消费去绕过 ready 门；正式当前消费必须满足 ready、当前 revision 与精确 Edit readback。生产者就绪仍不等于消费工作项最终验收。

本地控制脚本检查阶段顺序、交付定位、拆解图片结构、证据身份及最终消费绑定关系；不会自动核实上述方法是否合适、生成任务是否真实执行、回读正文是否完整或视觉质量是否通过。本次采用已有字段和阶段内规格，不增加自动生成器、机器语义验收或默认人工审批。
