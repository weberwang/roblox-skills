# Roblox 游戏反馈与动效

反馈要强化玩家对已发生玩法结果的理解，不能代替服务器规则、命中判定或经济事实。开始前读取 gameplay 事件、视觉与音频登记及[Studio 插件路由](../roblox-development-workflow/references/studio-plugin-routing.md)。

凡包含角色或对象动画的反馈，先按[动画意图与接入合同](../roblox-development-workflow/references/animation-intent-contract.md)指定制作人、Rig/Animator、AnimationId 权限、事件语义及重生/中断清理；Studio 插件没有自动动画制作、录制或导出工具，不能从网格生成或技术接线推断动画已完成。

## 职责与输入

- Gameplay 拥有权威状态、事件语义、动作触发和数值；juice 负责已确认事件的表现映射与生命周期。
- 读取真实 Animation、Sound、ParticleEmitter、UI 和对象池结构；确认表现应运行在客户端还是服务器。
- 事件含新的规则、击退、顿帧或输入控制时交回 gameplay/balance 评估，不把效果逻辑扩大为玩法实现。
- 特殊视觉方向或主要反馈语义有实质取舍时交给制作策划；常规强度与时长按已批准目标完成。
- 若反馈涉及新的玩法权限、刺激预算或目标选择且证据不能消除歧义，交[拷问技能](../roblox-game-grilling/SKILL.md)，不以效果制作替用户决定规则。

## 执行步骤

1. 为事件记录来源、玩家应理解的信息、参数、触发时机、消费端、表现通道和优先级。
2. 明确动画、声音、粒子、Tween、相机与 UI 各自的强度、时长、重复策略和停止条件。
3. 同类事件快速重复时，选择重播、重置、合并、限频或忽略，并验证不会掩盖重要玩法信息。
4. 多类事件叠加时规定优先级和并发上限；避免多个效果同时争写同一属性。
5. 对角色重生、玩家退出、对象池复用和界面关闭时的 AnimationTrack、Tween、连接、延迟任务及临时属性定义清理。
6. 客户端只播放反馈，不据此授予奖励或确认命中；服务器事实到达前可展示清晰的等待态。
7. 检查暂停、重生、离场和资源缺失后的行为；完成反馈后恢复被临时修改的属性。

## 交付与验证

- 交付事件映射表、资源身份、触发端、强度/时长、重复与叠加规则、优先级和清理策略。
- 使用 Studio 实例和脚本检查确认连接及资源路径；用户授权运行后记录实际重复、叠加和中断轨迹。
- QA 按正常触发、快速重复、峰值叠加、打断、重生、暂停及退出逐项验收。
- 数值结算由 [玩法开发](../roblox-gameplay-development/SKILL.md) 负责；音频和资源来源分别参考 [音频](../roblox-game-audio/SKILL.md) 与 [视觉资源](../roblox-game-visual-assets/SKILL.md)。
- 需要画面验收时提供截图和检查要点，等用户人工判断显示效果；不自动判图。

不要让相机/动画/UI 改写服务器权威状态。不要遗留循环任务、事件连接或对象池实例上的旧反馈状态。

## 表现冲突处理

- 命中确认、受伤数值、奖励结果和回合状态由服务器事件驱动；预测动画需能在结果被拒绝时收尾。
- 高优先级反馈可中断低优先级表现，但结束后恢复被覆盖的透明度、颜色、速度和音量。
- 对同一角色属性只指定一个主写入表现，其他反馈使用独立层或合成策略。
- 触控和小屏场景减少长期遮挡；关键事件不可只靠颜色、屏幕震动或音效区分。
- 持续视觉特效应按玩家距离、可见性或玩法状态回收，限制同屏数量。
- 动画载入失败时回退至清晰的基础姿态或事件提示，不让玩法状态等待表现资源。
- 对局结束、菜单打开和玩家死亡时，取消不再有意义的反馈序列。
- 多人共享的世界反馈标明复制责任；仅本地相机或 HUD 效果留在客户端。
- QA 需分别检查单次效果、快速连续触发和多事件叠加，不从资源预览推断实际表现。
