# Roblox 游戏发布与交付

发布准备必须绑定实际 Experience、Place 和版本状态。开始前读取[插件路由](../roblox-development-workflow/references/studio-plugin-routing.md)、[控制模型](../roblox-game-workflow-control/references/control-model.md)、资源许可、QA 证据和在线数据变更记录。

## 职责与输入

- 通过 list_roblox_studios 确认 Studio 实例；get_studio_state 只报告运行模式和可用 DataModel，不提供 Place 身份。以经核实的只读查询或用户提供信息确认 Experience/Place。
- 检查用户批准的目标玩家/平台、版本变更、Remote 安全、资源权限、隐私说明和已知风险；只有需求明确要求时才评估存量数据迁移或旧客户端兼容，默认不增加旧版兼容层。
- 发布目标、公开范围、商业化、数据处理、在线服务写入或回滚影响有实质选择时，先整理事实、选项、影响与推荐。
- 若发布对象/范围、资源许可、公开状态、商业化、数据风险或回滚影响仍有无法由证据消除的人工取舍，交给[Roblox 游戏拷问](../roblox-game-grilling/SKILL.md)取得并记录明确决定；准备就绪不等于获准上传或发布。获批后回交原发布工作项。
- Studio 插件当前没有 publish/build 工具路由；本技能可准备审查材料和人工步骤，不得虚构发布已完成。

## 发布准备步骤

存在[项目清单](../roblox-game-workflow-control/references/project-contract.md)时，发布工作项传递依赖最终集成项并固定其候选。发布前用 `status-project` 核对生产和集成项已完成；发布项因尚无发布结果而未完成是正常状态，不能预填 PASS。取得已授权的真实发布结果后，再用 `check-project` 聚合最终交付。多 Place 仅按项目显式配置检查各目标、关系契约与证据，不自动发布其他 Place。

1. 建立候选清单：Experience/Place 身份、来源改动、版本说明、功能范围、依赖、资源 ID 和批准的平台范围。
2. 核对已完成的 QA 结果、控制台错误、未覆盖的多人/设备场景和遗留阻断；开发者自检不能代替独立 QA。
3. 审核 Remote 校验和服务端权威、Player 生命周期清理、Streaming 假设、PurchaseId 幂等及线上回滚影响；仅在项目明确要求时审查存量数据迁移或旧客户端兼容。
4. 逐项确认模型、音频、字体、纹理、动画和外部资产授权；保留来源与使用范围。
5. 起草体验描述、更新说明、隐私/数据处理变化、目标玩家可见功能和已知问题，不夸大尚未验证的行为。
6. 准备分阶段启用和回滚计划：触发阈值、监控指标、责任人、恢复配置/版本路径和数据无法回滚时的补救方案。
7. 将实际提交发布、改写线上配置、上传或公开设为独立受保护操作；只有明确授权后才进入相应的人工发布流程。

## 交付与放行

- 交付候选清单、QA/资源/许可/数据证据索引、已知问题、灰度计划、回滚计划和人工步骤。
- 明确哪些检查通过、失败、阻断或未运行；无发布工具结果时状态保持“未发布”。
- 通过可验证的信息核对发布主体、目标 Place 和版本记录；get_studio_state 不作为 Place 身份证据，信息缺失或不一致时标未验证并交回策划确认。
- 发布后记录实际外部结果、可见版本和回滚状态；不得把准备就绪写成已上线。
- QA 放行依据 [QA 与性能](../roblox-game-qa-performance/SKILL.md) 的实际证据；候选范围来自 [制作策划](../roblox-game-production/SKILL.md)。

不要自行启用线上 DataStore、公开体验、上传资源或进行发布。任何缺失的批准、许可、QA 证据或候选身份都应作为阻断项。

## 回滚与事故准备

- 回滚步骤要与实际 place/version 管理方式相符，并事先确认是否会影响已保存玩家数据。
- 不能用代码版本回退自动撤销已发放购买、已写入存档或已发送的玩家通知。
- 只有项目明确要求存量数据兼容/迁移时，才为新增、删除或改名字段设计旧记录处理；默认按当前目标数据格式实施，不增加旧版兼容层。
- 发布清单应记录关键资产 ID 和许可状态，避免发布时因私有资产或审核状态不可用而空白。
- 对关键体验流程列出公开访问前必须复核的权限、隐私、交易和 UGC 入口。
- 回滚候选应保留可核实的版本身份、变更记录、恢复责任人和观察窗口。
- 外部平台审批、可发现性、公开状态和实际线上玩家行为不能由本地 Studio 状态推断。
- 若无权读取 Creator Dashboard 或线上版本状态，将相应项标为未验证并交由体验所有者检查。
